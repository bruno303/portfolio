## Contexto

Qualquer cloud gerenciada esconde a maior parte do ciclo operacional: DNS, TLS,
scheduling, secrets e observabilidade viram itens de fatura. Em casa, cada um desses é
uma decisão — e é exatamente por isso que vale a pena. O objetivo era ser dono do
ciclo inteiro, do `kubectl` ao teste de restore; economizar com hospedagem nunca foi
o ponto.

## O que roda lá

Um cluster k3s com serviços que importam para mim: Gitea com runners de CI, Vaultwarden,
Immich, Jellyfin, Memos, ntfy, Open WebUI, PDFding e o dashboard de homepage — além
da própria stack de observabilidade: OpenTelemetry Collector, Prometheus, Loki, Tempo e
Grafana. Os serviços foram implantados em momentos diferentes, e nem todos rodam o
tempo todo.

A entrega é feita pelo ArgoCD, uma aplicação por serviço, com a configuração do próprio
cluster aplicada como uma aplicação separada.

## Decisões e trade-offs

- **GitOps ou não existe.** Nada é aplicado na mão. Se não está no Git, é um incidente
  futuro. Os manifests no repositório são a única verdade, e drift é bug.
- **Secrets nunca vivem no Git.** O External Secrets Operator sincroniza de secret
  stores por ambiente, então o repositório pode ficar público sem virar risco.
- **Túnel para dentro, não portas para fora.** O Cloudflare Tunnel publica serviços sem
  abrir uma única porta de entrada e mantém o IP de casa invisível.
- **Observabilidade como um pipeline só.** As aplicações emitem OTLP; um gateway do
  collector distribui traces para o Tempo, métricas para o Prometheus (remote write) e
  logs para o Loki. Um pipeline significa um único lugar para depurar quando a
  telemetria some — isso já aconteceu de verdade, e o conserto virou uma mudança na
  config do collector, não em nove aplicações.
- **Backup é código, e código é testado.** Snapshots com `restic` são copiados para um
  pendrive externo via `rclone` todos os dias às 03:00 (BRT), guiados por um Makefile,
  com um verificador que confere os snapshots. As lacunas restantes (snapshot de etcd,
  drill completo de restore) ficam
  rastreadas como itens abertos no próprio repositório, em público — lista de TODO pela
  metade é o estado normal de um sistema em uso.

## Resultados e próximos passos

Cerca de quinze serviços rodam sem supervisão, deploys chegam por Git push, e o pipeline
de telemetria virou o mesmo para o qual o portfólio e o planning-poker reportam — ou
seja, problemas nele são notados imediatamente.

O que vem a seguir, já rastreado no repositório:

- Snapshot de etcd para o estado do próprio cluster (a única coisa que o restic ainda
  não cobre).
- Um drill de restore de verdade: restaurar o Vaultwarden em um diretório temporário e
  provar que o banco abre.
- Migrar as últimas configurações feitas por UI (datasources do Grafana) para arquivos
  de values.
