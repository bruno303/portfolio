## Context

Any managed cloud hides most of the operational loop: DNS, TLS, scheduling, secrets
and observability arrive as line items. At home, every one of those is a decision —
which is exactly why it is useful. The goal was to own the whole loop, from `kubectl`
to restore drills; saving money on hosting was never really the point.

## What runs there

A k3s cluster running services that matter to me: [Gitea](https://gitea.com) with CI
runners, Vaultwarden, Immich, Jellyfin, Memos, ntfy, Open WebUI, PDFding and the
homepage dashboard — plus the observability stack itself: OpenTelemetry Collector,
Prometheus, Loki, Tempo and Grafana. The services were deployed at different times,
and not all of them are always running.

Delivery is ArgoCD, one application per service, with the cluster's own configuration
(GitOps settings, namespaces, repository config) applied as its own application.

## Decisions and trade-offs

- **GitOps or it does not exist.** Nothing is applied by hand. If it is not in Git, it
  is a future incident. The chart or manifests in the repository are the only truth,
  and drift is a bug.
- **Secrets never live in Git.** External Secrets Operator syncs from external secret
  stores per environment, so the repository can stay public-ish and still be safe.
- **Tunnel in, not ports out.** Cloudflare Tunnel publishes services without opening a
  single inbound port, and keeps the home IP invisible. TLS terminates at the edge.
- **Observability as one pipeline.** Applications emit OTLP; a collector gateway fans
  out traces to Tempo, metrics to Prometheus (remote write) and logs to Loki. Node-level
  scraping stays in Prometheus. One pipeline means a single place to debug when
  telemetry disappears — that happened once, and the fix went into the collector's
  config rather than nine applications.
- **Backups are code, and code gets tested.** `restic` snapshots are copied to an
  external drive with `rclone` every day at 03:00 BRT, driven by a Makefile, with a
  verifier that checks the snapshots. The remaining gaps (etcd snapshots, a full
  restore drill) are tracked as
  open items in the repository itself, in the open — a half-finished TODO list is just
  what a working system looks like.

## Results and next steps

Around fifteen services run unattended, deployments arrive by Git push, and the
telemetry pipeline has become the same one the portfolio and the planning-poker app
report to — which means problems in it get noticed immediately.

What is next, already tracked in the repository:

- etcd snapshot backups for the cluster's own state (the one thing restic does not
  cover yet).
- A real restore drill: restore Vaultwarden to a temporary directory and prove the
  database opens.
- Moving the last UI-configured pieces (Grafana datasources) into values files.
